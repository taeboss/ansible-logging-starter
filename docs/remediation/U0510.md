# U0510 - OpenSSL 버전 취약성

## 진단 기준

- 양호: 지원 중인 OS 공식 저장소에서 제공하는 OpenSSL 보안 수정 패키지가
  적용되어 있고 추가로 설치할 OpenSSL 관련 업데이트가 없다.
- 취약: OpenSSL 관련 보안 업데이트가 남아 있거나 지원이 종료된 패키지 또는
  출처를 확인할 수 없는 별도 설치본을 사용한다.

배포판 패키지는 보안 수정사항을 이전 upstream 버전에 백포트할 수 있으므로
`openssl version` 숫자만으로 양호·취약을 판단하지 않는다. OS 패키지의 전체
버전과 공식 보안 공지를 기준으로 판단한다.

소스 컴파일 등 upstream OpenSSL을 직접 운영하는 경우에만 다음 권고 버전을
직접 비교한다.

| 계열 | upstream 권고 버전 |
|---|---|
| 1.0.2 | 1.0.2zl |
| 1.1.1 | 1.1.1zb |
| 3.0 | 3.0.16 |
| 3.1 | 3.1.8 |
| 3.2 | 3.2.4 |
| 3.3 | 3.3.3 |
| 3.4 | 3.4.1 |

관련 upstream 권고:
<https://openssl-library.org/news/secadv/20250120.txt>

## 구현 상태

| 구분 | Red Hat 계열 | Ubuntu |
|---|---|---|
| 플레이북 | `playbooks/controls/U0510-redhat.yml` | `playbooks/controls/U0510-ubuntu.yml` |
| 대상 패키지 | 설치된 `openssl`, `openssl-libs` | 설치된 `openssl`, `libssl` 런타임 패키지 |
| 패키지 관리자 | DNF 또는 DNF5 자동 선택 | APT |
| 업데이트 범위 | 대상 패키지만 `latest` | 대상 패키지만 `latest` |
| 서비스 재시작·재부팅 | 결과만 확인 | 결과만 확인 |

전체 상태는 🟡 부분 적용이다. 패키지 업데이트는 자동 조치하며 업무 서비스
재시작 또는 서버 재부팅은 담당자가 영향도를 확인한 후 직접 수행한다.

## 자동 조치

플레이북은 다음 순서로 작업한다.

1. 대상 OS와 현재 설치된 패키지를 확인한다.
2. 설치된 OpenSSL 실행 패키지와 라이브러리만 조치 대상으로 선정한다.
3. 변경 전 패키지의 전체 버전을 기록한다.
4. 활성화된 OS 공식 저장소에서 대상 패키지만 최신 버전으로 업데이트한다.
5. 같은 패키지에 추가 업데이트가 남았는지 점검 모드로 다시 확인한다.
6. 변경 후 패키지 전체 버전과 `openssl version -a`를 출력한다.
7. OS의 재부팅 필요 상태를 확인하고 결과를 출력한다.

전체 패키지 업데이트, 신규 OpenSSL 패키지 설치, source build, 서비스 재시작과
서버 재부팅은 수행하지 않는다. Ubuntu는 패키지 작업 중 서비스가 자동으로
재시작되지 않도록 `policy_rc_d=101`을 임시 적용하고 작업 후 원상복구한다.

## 실행 방법

먼저 대상 한 대에서 공식 저장소 접근과 변경 예정 패키지를 확인한다.

```bash
ansible-playbook playbooks/controls/U0510-redhat.yml \
  --limit REDHAT_TARGET --check --diff

ansible-playbook playbooks/controls/U0510-ubuntu.yml \
  --limit UBUNTU_TARGET --check --diff
```

점검 결과를 검토한 후 `--check --diff`를 제거하여 실제 적용한다. 한 번에 한
서버만 처리하며 다른 OS의 호스트는 변경하지 않는다.

## 검증 및 직접 조치

플레이 결과에서 다음 항목을 확인한다.

- 변경 전·후 RPM 또는 DEB 전체 패키지 버전
- `openssl version -a` 출력
- 활성 저장소에 남은 OpenSSL 관련 업데이트가 없는지 여부
- 재부팅 필요 여부
- Ubuntu에서 `needrestart`가 제공하는 재시작 대상

업데이트된 라이브러리를 기존 프로세스가 계속 사용하고 있으면 유지보수 시간에
업무 담당자와 협의하여 해당 서비스를 재시작한다. 재부팅 필요 결과가 표시되면
조직의 서버 재부팅 절차에 따라 별도 수행한다.

## 예외 및 롤백

- 내부 저장소가 공식 보안 패키지를 아직 동기화하지 않았다면 조치를 완료로
  판정하지 않고 저장소 동기화 후 다시 실행한다.
- 버전 고정 또는 제외 설정 때문에 업데이트가 남으면 자동으로 우회하지 않고
  해당 정책을 검토한다.
- 별도 설치한 upstream OpenSSL은 이 플레이북의 대상이 아니며 별도 검토한다.
- 패키지 downgrade는 라이브러리 의존성 위험이 있으므로 자동 롤백하지 않는다.
  장애 시 VM 스냅샷 또는 승인된 이전 패키지 세트를 사용하여 관련 패키지를
  일관되게 복구한다.
