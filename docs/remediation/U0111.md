# U0111 - 계정이 존재하지 않는 GID 금지

## 진단 기준

- 양호: 시스템 관리와 운영에 불필요한 그룹이 없거나, 구성원이 없는 그룹의
  생성 목적과 사용 여부를 확인하여 필요한 그룹으로 관리하고 있다.
- 취약: 시스템 관리와 운영에 불필요한 그룹이 존재하고 해당 그룹의 필요성과
  사용 여부를 확인하지 않았다.

불필요한 그룹이 남아 있으면 해당 GID가 소유한 파일이나 장치가 의도하지 않은
계정에 노출될 수 있으므로 관리자 검토 후 정리한다.

## 진단 범위 유의사항

다음 세 가지는 서로 다른 상태이므로 구분해서 확인해야 한다.

1. `/etc/group`의 구성원 목록이 비어 있는 그룹
2. 그룹 구성원 목록에 실제로 존재하지 않는 계정명이 남은 경우
3. 파일의 숫자 GID에 대응하는 그룹 정보가 없어 소유 그룹을 확인할 수 없는 경우

`/etc/group`의 마지막 구성원 칸에는 보조 그룹 구성원만 표시된다. 이 값이
비어 있어도 `/etc/passwd`에서 해당 GID를 기본 그룹으로 사용하는 계정이 있을
수 있으므로 구성원 없음으로 단정하지 않는다. 로컬 파일만 비교하지 않고
SSSD·LDAP 등 NSS를 통해 제공되는 계정과 그룹도 `getent`로 확인한다.

## 진단 예시

그룹과 전체 계정의 기본 GID를 조회한다.

```bash
getent group
getent passwd
getent group GROUP_NAME
getent passwd | awk -F: -v gid=GROUP_GID '$4 == gid { print $1 ":" $4 }'
```

그룹이 소유한 일반 파일과 디렉터리는 파일시스템별로 확인한다.

```bash
sudo find / -xdev -gid GROUP_GID -print
```

별도 마운트, 네트워크 파일시스템과 컨테이너 경로는 범위를 명확히 지정해 따로
확인한다.

현재 진단에서 구성원 미존재로 확인된 그룹은 다음과 같다.

| 그룹 | GID |
|---|---:|
| `render` | 109 |
| `bluetooth` | 112 |
| `_ssh` | 118 |
| `sgx` | 134 |
| `rdma` | 137 |

위 이름과 GID는 진단 대상 서버의 결과이며 다른 서버나 OS에서 동일하다고
가정하지 않는다.

## 권고 조치 방법

구성원이 없는 그룹은 다음 사항을 관리자와 검토한 후 불필요한 로컬 그룹으로
확정된 경우에만 제거한다.

```bash
sudo groupdel GROUP_NAME
```

`/etc/group`을 일반 편집기로 직접 수정하지 않는다. 존재하지 않는 계정명만
로컬 그룹 구성원 목록에서 정리해야 하는 예외 상황은 원본 백업과 파일 잠금을
보장하는 관리 절차를 사용한다.

## 구현 상태

| 구분 | Red Hat 계열 | Ubuntu |
|---|---|---|
| 상태 | ⚪ 미구현(검토 보류) | ⚪ 미구현(검토 보류) |
| 실행 플레이북 | 미작성 | 미작성 |
| Role 태스크 | 미작성 | 미작성 |
| 현재 자동 조치 | 없음 | 없음 |

현재 저장소에는 U0111 점검 또는 그룹 삭제 플레이북이 없다. 그룹 정보와
`/etc/group`을 변경하지 않는다.

## 미구현 사유와 우려사항

진단된 그룹 중에는 OS 설치나 패키지 설치 과정에서 생성되는 시스템 그룹이
포함될 수 있다. 현재 구성원이 없더라도 장치 접근, 파일 소유권, 향후 서비스
기동 또는 패키지 기능에 필요할 수 있으며 서버별 설치 패키지와 역할에 따라
필요 여부가 달라진다.

다음 사항을 서버별로 확인해야 하므로 자동 삭제를 보류한다.

1. 해당 GID를 기본 그룹으로 사용하는 로컬·외부 계정 존재 여부
2. `/etc/group`에 등록된 보조 구성원이 실제로 존재하는지 여부
3. 해당 그룹이 소유한 파일, 디렉터리, 장치와 별도 마운트 데이터
4. 그룹을 생성하거나 참조하는 OS 기본 구성, 패키지, 서비스와 udev 규칙
5. SSSD·LDAP 등 외부 계정 저장소에서 제공되는 사용자·그룹 여부
6. 그룹 삭제 후 서비스 기동, 장치 접근과 패키지 업데이트에 미치는 영향

특히 `render`, `bluetooth`, `sgx`, `rdma`, `_ssh` 같은 시스템 그룹은 현재
구성원이 없다는 이유만으로 일괄 삭제하지 않는다.

## 직접 조치 방침

서버별 진단 결과를 담당자가 검토한 후 다음 중 하나로 개별 처리한다.

- OS·패키지·서비스에서 사용하는 그룹이면 유지하고 설정 이유를 기록한다.
- 현재 구성원은 없지만 향후 기능이나 장치 접근에 필요한 그룹이면 승인된 예외로
  기록한다.
- 계정, 파일, 장치, 패키지와 외부 저장소에서 사용하지 않는 로컬 그룹으로
  확인된 경우에만 `groupdel`로 제거한다.
- 판단 근거가 부족하면 변경하지 않고 OS 또는 서비스 담당자에게 확인한다.

## 조치 후 확인

그룹을 제거한 경우 그룹 조회 결과, 숫자 GID만 남은 파일과 관련 서비스 상태를
다시 확인한다.

```bash
getent group GROUP_NAME
sudo find / -xdev -gid GROUP_GID -print
```

작업 결과에는 서버명, 그룹명, GID, 유지·삭제 사유, 관련 패키지·서비스,
변경 전후 확인 결과와 승인자를 기록한다.
