# U0307 - 서비스 Banner 관리

## 진단 기준

- 양호: SSH, Telnet, FTP, SMTP, DNS가 실행 중이 아니거나, 실행 중인
  서비스의 배너에 OS·호스트명·버전 정보가 노출되지 않는다.
- 취약: 실행 중인 서비스의 배너에 OS·호스트명·버전 정보가 노출된다.

접속 전 문구는 인가된 사용자만 사용할 수 있고 활동이 모니터링·기록될
수 있음을 알리는 고정 경고문으로 관리한다.

## 구현 상태

| 구분 | Red Hat 계열 | Ubuntu |
|---|---|---|
| 사용 현황 점검 | `playbooks/controls/U0307-check.yml` | 동일 |
| SSH 자동 조치 | `playbooks/controls/U0307-ssh.yml` | 동일 |
| 점검 Role 태스크 | `u0307_check_redhat.yml` | `u0307_check_ubuntu.yml` |
| SSH Role 태스크 | `u0307_ssh_redhat.yml` | `u0307_ssh_ubuntu.yml` |
| 경고문 | `/etc/issue`, `/etc/issue.net` | 동일 |
| SSH 자동 조치 | `Banner`, `VersionAddendum` | `Banner`, `VersionAddendum`, `DebianBanner` |
| Telnet·FTP·SMTP·DNS | 패키지·systemd·프로세스·포트·설정 현황 점검 | 동일 |

전체 상태는 🟡 부분 적용이다. SSH와 공통 경고문은 자동 조치하고,
Telnet·FTP·SMTP·DNS는 실제 제품과 업무 프로토콜을 확인한 후 직접
조치해야 한다.

## 사용 현황 자동 점검

`U0307-check.yml`은 SSH·Telnet·FTP·SMTP·DNS에 대해 다음을 읽기
전용으로 수집한다.

- OS 패키지 설치 여부
- systemd unit 존재·실행 상태
- 실행 프로세스
- TCP·UDP LISTEN 포트
- 제품별 설정 파일과 활성 배너 지시문

각 서비스는 다음 상태 중 하나로 표시한다.

- `LISTENING`: 대상 포트가 실제로 수신 중
- `ACTIVE_NOT_LISTENING`: 서비스나 프로세스는 실행 중이지만 대상 포트는 미확인
- `INSTALLED_INACTIVE`: 패키지·unit·설정 파일은 있지만 실행·수신 중이 아님
- `NOT_INSTALLED`: 설치·실행·설정 흔적이 확인되지 않음

이 상태는 사용 현황 확인을 위한 참고값이며 U0307 양호·취약 판정 결과가 아니다.
점검 플레이북은 서비스를 시작·중지하거나 설정 파일을 변경하지 않는다.

## SSH 자동 조치

`U0307-ssh.yml`은 다음 순서로 작업한다.

1. `login_warning_text`를 `/etc/issue`, `/etc/issue.net`에 배포한다.
   파일이 없으면 생성하고 기존 파일은 백업한 후 root 소유와 `0644` 권한으로 관리한다.
2. SSH 실행 파일과 서비스 활성 상태를 확인한다.
3. SSH가 실행 중이면 변경 전 `sshd -t`와 `sshd -T`를 실행한다.
4. `/etc/ssh/sshd_config` 앞부분에 U0307 전용 관리 블록을 적용한다.

   Red Hat 계열:

   ```text
   Banner /etc/issue.net
   VersionAddendum none
   ```

   Ubuntu:

   ```text
   Banner /etc/issue.net
   VersionAddendum none
   DebianBanner no
   ```

5. 원본을 백업하고 `sshd -t -f`로 변경 파일을 검사한다.
6. 실제 적용에서는 `sshd -T`의 최종 유효값을 검증한 후에만 SSH 서비스를
   reload하고 `active` 상태를 다시 확인한다.

SSH가 실행 중이 아니면 SSH 설정과 서비스는 변경하지 않는다.

## 제한사항과 유의사항

- `VersionAddendum none`은 추가 문자열을 제거하지만 OpenSSH 프로토콜의 기본
  제품·버전 식별 문자열까지 완전히 숨기지는 못한다.
- MOTD는 일반적으로 인증 후에 표시되는 안내문으로 SSH 사전 인증
  `Banner`와 구분한다. `/etc/motd`, `/run/motd.dynamic`, `/etc/update-motd.d/`는
  U0307 사용 현황 점검과 자동 조치 범위에서 제외한다.
- `login_warning_text`에는 호스트명, OS, 제품명, 버전과 같은 시스템 정보를
  넣지 않는다.
- `login.cfg`, `ftpd.cat`, `dspcat`, `gencat` 방식은 레거시 UNIX나 특정 FTP
  구현에 해당할 수 있어 현재 Red Hat·Ubuntu에 일괄 적용하지 않는다.

## 제품별 직접 조치

`U0307-check.yml` 출력의 패키지·서비스·프로세스·수신 포트·설정 파일을
기준으로 실제 사용 제품을 먼저 확인한다. 미사용 서비스를 새로
설치하거나 활성화하지 않는다.

- Telnet: 실제 telnet daemon이 어떤 파일을 배너로 사용하는지 확인하고
  승인된 경고문을 설정한다.
- vsftpd: 실제 설정 파일에 `ftpd_banner`나 `banner_file`을 적용하고
  설정과 새 FTP 접속을 검증한 후 서비스를 반영한다.
- ProFTPD: `ServerIdent` 지시문을 호스트명·버전이 없는 승인 문구로
  설정하고 구문 검사 후 서비스를 반영한다.
- wu-ftpd: 레거시 제품으로 분류하고 제거·대체 가능성을 우선 검토한다.
- Postfix·Sendmail: SMTP 인사 문구는 프로토콜과 메일 연동에 영향을 줄 수
  있으므로 메일 담당자가 승인한 식별 문구로 수정하고 구성 검사 후
  서비스를 반영한다.
- BIND: `options` 블록의 `version` 지시문을 승인된 비노출 문구로 설정하고
  `named-checkconf`를 통과한 후 DNS 서비스를 reload한다.

## 실행 및 검증

먼저 사용 현황을 점검한다.

```bash
ansible-playbook playbooks/controls/U0307-check.yml \
  --limit TARGET
```

이후 대상 한 대에서 SSH 변경 예정 내용을 점검 모드로 확인한다.

```bash
ansible-playbook playbooks/controls/U0307-ssh.yml \
  --limit TARGET --check --diff
```

결과를 검토한 후 `--check --diff`를 제거하여 실제 적용한다. 적용 후에는
기존 SSH 세션을 유지한 상태에서 다음을 확인한다.

```bash
sudo sshd -t
sudo sshd -T | grep -Ei '^(banner|versionaddendum|debianbanner) '
cat /etc/issue /etc/issue.net
ss -lntup
```

별도 터미널에서 새 SSH 접속을 시도해 인증 전 경고문과 정상 로그인을
확인한다. Telnet·FTP·SMTP·DNS는 실제 원격 접속이나 질의로 배너를 별도
확인한다. 적용과 직접 조치 후 `U0307-check.yml`을 다시 실행해 상태를
비교한다.

## 롤백

SSH 적용 또는 새 접속 검증에 실패하면 기존 관리자 세션을 유지한 상태에서
Ansible이 생성한 `/etc/ssh/sshd_config`, `/etc/issue`, `/etc/issue.net` 백업본을
복원한다. SSH 설정은 `sshd -t`가 성공한 경우에만 OS별 SSH 서비스에
반영한다. 직접 조치한 서비스는 각 제품의 작업 전 백업본으로 복원한다.
