# U0308 - Session Timeout 설정

## 진단 기준

- 양호: `/etc/profile`을 통해 새 로그인 셸에 적용되는 `TMOUT` 유효값이
  1초 이상 300초 이하이다.
- 취약: `TMOUT`이 없거나, 0·비숫자 값이거나, 유효값이 300초를 초과한다.

`TMOUT`은 Bash에서 입력 없이 대기한 시간을 기준으로 셸을 자동 종료하는 값이다.
이미 1~300초로 설정된 서버는 더 느슨한 300초로 변경하지 않는다.

## 구현 상태

| 구분 | Red Hat 계열 | Ubuntu |
|---|---|---|
| 실행 플레이북 | `playbooks/controls/U0308.yml` | `playbooks/controls/U0308.yml` |
| Role 태스크 | `u0308_redhat.yml` | `u0308_ubuntu.yml` |
| 적용 파일 | `/etc/profile` | `/etc/profile` |
| 자동 조치 | 비정상 기존 지시문 정리, 미설정·0·비숫자·300초 초과 시 300초 | 동일 |
| 기존 1~300초 | 기존 값을 유지 | 기존 값을 유지 |
| 서비스 재시작·재부팅 | 불필요 | 불필요 |

전체 상태는 ✅ 자동 조치 완료이다. 통합 플레이북이 대상 OS를 식별하고 두 OS
Role은 같은 검증된 공통 태스크를 사용한다.

## 자동 조치

플레이북은 다음 순서로 작업한다.

1. `/etc/profile`이 일반 파일인지 확인한다.
2. 변경 전에 `bash -n /etc/profile`로 셸 구문을 검사한다.
3. 현재 활성 `TMOUT` 설정 행과 새 로그인 셸의 유효값을 기록한다.
4. 원본을 백업하고 파일 끝에 U0308 전용 관리 블록을 추가한다.
5. 기존 유효값이 300초를 초과하거나 0·비숫자이면 관리 블록 앞에 있는 활성
   `TMOUT`, `readonly TMOUT`, `export TMOUT` 지시문을 제거한다.
6. 기존 유효값이 1~300이면 유지하고, 그 외에는 `TMOUT=300`으로 설정한다.
7. `TMOUT`을 `readonly`와 `export`로 선언한다.
8. 변경 후 셸 구문과 새 로그인 셸의 실제 유효값을 검증한다.
9. 검증 실패 시 작업 전 백업본으로 `/etc/profile`을 복원한다.

전용 관리 블록은 `/etc/profile.d/*.sh` 처리 이후인 `/etc/profile` 끝에 추가되어
앞에서 설정된 값도 최종적으로 기준에 맞춘다. 이미 앞부분에서 `TMOUT`이 읽기
전용으로 고정된 경우도 `/etc/profile`의 관리 블록 앞에 있으면 기존 지시문을
정리한 뒤 관리 블록으로 통합한다. `/etc/profile.d`나 사용자별 시작 파일처럼
이 플레이북의 범위 밖에서 다시 고정하는 구성은 검증 단계에서 실패한다.

## 실행 방법

먼저 대상 한 대에서 점검 모드로 변경 예정 내용을 확인한다.

```bash
ansible-playbook playbooks/controls/U0308.yml \
  --limit TARGET --check --diff
```

점검 결과를 검토한 후 `--check --diff`를 제거하여 실제 적용한다. 통합
플레이북은 facts로 Red Hat 계열과 Ubuntu를 판별하고 자체적으로 한 번에 한
서버만 처리한다.

## 검증

플레이 결과에서 변경 전·후 `TMOUT` 행, 새 로그인 셸의 유효값과 백업 파일을
확인한다. 대상 서버에서 직접 확인하려면 다음 명령을 사용한다.

```bash
grep -nE '^[[:space:]]*(export[[:space:]]+)?TMOUT[[:space:]]*=' /etc/profile

env -u TMOUT bash --noprofile --norc -c \
  '. /etc/profile >/dev/null 2>&1; printf "%s\n" "${TMOUT-}"'
```

실제 사용자의 새 로그인 세션에서도 `printf '%s\n' "$TMOUT"` 결과가 1~300인지
확인한다. 기존에 열린 세션에는 소급 적용되지 않으므로 재접속 후 검증한다.

## 영향 및 롤백

- 300초 동안 셸 입력이 없으면 해당 대화형 Bash 세션이 종료될 수 있으므로
  장시간 대화형 작업은 `tmux`, `screen` 또는 승인된 작업 자동화를 사용한다.
- 실행 중인 서비스, 비대화형 작업과 기존 로그인 세션은 즉시 종료되지 않는다.
- 서비스 재시작이나 서버 재부팅은 필요하지 않다.
- 검증 실패 시 플레이북이 자동 복원한다. 적용 후 수동 롤백이 필요하면 출력된
  백업 파일을 `/etc/profile`로 복원하고 `bash -n /etc/profile`을 확인한다.
