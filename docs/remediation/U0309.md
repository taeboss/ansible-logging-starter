# U0309 - root 계정 Telnet·SSH 접근 제한

## 진단 기준

- 양호: Telnet 및 SSH 접속 시 root 계정으로 직접 접속할 수 없다.
- 취약: Telnet 또는 SSH 접속 시 root 계정으로 직접 접속할 수 있다.

root 계정의 원격 직접 접속을 제한하고 일반 관리계정으로 로그인한 뒤 승인된
`sudo` 또는 `su` 절차를 사용한다.

## 구현 상태

| 구분 | Red Hat 계열 | Ubuntu |
|---|---|---|
| 플레이북 | `playbooks/controls/U0309-redhat.yml` | `playbooks/controls/U0309-ubuntu.yml` |
| SSH 서비스 | `sshd` reload | `ssh` restart |
| SSH 자동 조치 | `PermitRootLogin no`, `PermitEmptyPasswords no` | 동일 |
| Telnet | 현황 확인만 수행 | 현황 확인만 수행 |

전체 상태는 🟡 부분 적용이다. SSH는 자동 조치하며 Telnet은 직접 조치해야 한다.

## SSH 자동 조치

플레이북은 다음 순서로 작업한다.

1. 대상 OS와 `/usr/sbin/sshd`를 확인한다.
2. SSH 서비스와 기존 설정 구문이 정상인지 확인한다.
3. `/etc/ssh/sshd_config` 원본을 백업한다.
4. 다음 설정을 파일의 전역 영역에 적용한다.

   ```text
   PermitRootLogin no
   PermitEmptyPasswords no
   ```

5. `sshd -t`와 root 접속 조건의 `sshd -T` 유효 설정을 검증한다.
6. 검증 성공 시에만 OS별 SSH 서비스에 반영한다.
7. 서비스가 `active` 상태인지 다시 확인한다.

한 번에 한 서버만 처리하며 다른 OS의 호스트는 변경하지 않는다.

## Telnet 직접 조치

플레이북은 TCP/23 수신 상태와 `/etc/pam.d/login`, `/etc/securetty` 존재 여부만
확인한다. 다음 변경은 서버 담당자가 서비스 영향도를 확인한 후 직접 수행한다.

1. Telnet 서비스가 실제로 설치·활성화되어 있는지 확인한다.
2. `/etc/pam.d/login`과 `/etc/securetty`를 백업한다.
3. PAM 모듈이 존재하는지 확인하고 `/etc/pam.d/login`의 인증 스택 앞부분에
   다음 활성 행이 있는지 확인한다.

   ```text
   auth required pam_securetty.so
   ```

4. `/etc/securetty`가 없으면 담당자와 허용 콘솔 범위를 결정한 후 생성한다.
5. `/etc/securetty`의 `pts` 허용 행은 담당자 협의 후 제거한다.
6. 일반계정 Telnet 로그인과 승인된 `su` 전환은 가능하고 root 직접 로그인은
   거부되는지 확인한다.

Telnet이 설치되지 않았거나 TCP/23에서 수신하지 않으면 새로 설치하거나
활성화하지 않는다.

## 실행 방법

먼저 대상 한 대에서 점검 모드로 검토한다.

```bash
ansible-playbook playbooks/controls/U0309-redhat.yml \
  --limit REDHAT_TARGET --check --diff

ansible-playbook playbooks/controls/U0309-ubuntu.yml \
  --limit UBUNTU_TARGET --check --diff
```

결과를 검토한 후 `--check --diff`를 제거하여 실제 적용한다. 기존 관리자 SSH
세션과 콘솔 복구 경로를 유지한 상태에서 새 SSH 세션으로 root 직접 접속 거부,
일반 관리계정 접속 및 `sudo`를 확인한다.

## 롤백

SSH 적용 또는 새 세션 검증에 실패하면 기존 관리자 세션을 유지한 상태에서
Ansible이 생성한 `/etc/ssh/sshd_config` 백업본을 복원한다. 복원 파일에 대해
`sshd -t`가 성공한 경우에만 OS별 SSH 서비스를 다시 반영한다. Telnet 직접
조치는 작업 전 생성한 PAM 및 `securetty` 백업본으로 복원한다.
