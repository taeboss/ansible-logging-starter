# U0507 - SSH(Secure Shell) 버전 취약성

## 진단 기준

- 양호: SSH 서비스가 실행 중이 아니거나, 실행 중인 경우 지원 중인 OS 공식
  저장소의 OpenSSH 보안 수정 패키지가 적용되어 있고 추가 업데이트가 없다.
- 취약: SSH 서비스가 실행 중이며 OpenSSH 관련 보안 업데이트가 남아 있거나,
  지원이 종료된 패키지 또는 출처를 확인할 수 없는 별도 설치본을 사용한다.

`ssh -V`는 SSH 클라이언트 버전을 출력하며 SSH 서버 패키지의 보안 수정 상태를
완전히 증명하지 않는다. 배포판은 보안 수정사항을 이전 upstream 버전에 백포트할
수 있으므로 upstream 버전 숫자만으로 양호·취약을 판단하지 않고 OS 패키지의
전체 버전과 공식 보안 공지를 함께 확인한다.

예를 들어 CVE-2023-38408의 upstream 수정 버전은 OpenSSH 9.3p2지만 Ubuntu
22.04는 `1:8.9p1-3ubuntu0.3` 패키지에 수정사항을 반영했다. 따라서
`9.3p2 미만`만으로 Ubuntu 22.04를 취약하다고 판단하면 오탐이 발생할 수 있다.

## 구현 상태

| 구분 | Red Hat 계열 | Ubuntu |
|---|---|---|
| 실행 플레이북 | `playbooks/controls/U0507.yml` | `playbooks/controls/U0507.yml` |
| Role 태스크 | `u0507_redhat.yml` | `u0507_ubuntu.yml` |
| SSH 서비스 | `sshd.service` | `ssh.service`, `sshd.service` 또는 `ssh.socket` |
| 대상 패키지 | 설치된 `openssh*` 패키지 | 설치된 `openssh*` 패키지 |
| 패키지 관리자 | DNF 또는 DNF5 자동 선택 | APT |
| 서비스 재시작·재부팅 | 결과만 확인 | 결과만 확인 |

전체 상태는 🟡 부분 적용이다. SSH 서비스가 실행 중이면 패키지 업데이트는 자동
조치하지만, 현재 관리 세션 단절 위험이 있는 SSH 서비스 재시작과 서버 재부팅은
담당자가 영향도를 확인한 후 직접 수행한다.

## 자동 조치

플레이북은 다음 순서로 작업한다.

1. 대상 OS와 SSH 서비스 실행 상태를 확인한다.
2. 현재 설치된 OpenSSH 관련 패키지와 전체 버전을 기록한다.
3. SSH 서비스가 실행 중이면 변경 전 `sshd -t` 구문 검사를 수행한다.
4. 활성화된 OS 공식 저장소에서 설치된 OpenSSH 관련 패키지만 최신화한다.
5. 같은 패키지에 추가 업데이트가 남았는지 점검 모드로 다시 확인한다.
6. 변경 후 `sshd -t`와 SSH 서비스 실행 상태를 검증한다.
7. 패키지 버전, `ssh -V`, `sshd -V`와 재시작 필요 정보를 출력한다.

SSH 서비스가 실행 중이 아니면 진단 기준에 따라 패키지를 변경하지 않고 현황만
출력한다. 전체 패키지 업데이트, 신규 OpenSSH 설치, source build, SSH 서비스
재시작과 서버 재부팅은 수행하지 않는다. Ubuntu는 패키지 작업 중 서비스가
자동으로 재시작되지 않도록 `policy_rc_d=101`을 임시 적용하고 작업 후 원상복구한다.

## 실행 방법

현재 Ansible SSH 세션이 끊길 가능성을 줄이기 위해 먼저 시험 서버 한 대에서
점검 모드로 확인한다.

```bash
ansible-playbook playbooks/controls/U0507.yml \
  --limit TARGET --check --diff
```

점검 결과를 검토한 후 `--check --diff`를 제거하여 실제 적용한다. 통합
플레이북이 facts로 대상 OS를 판별하며 한 번에 한 서버만 처리한다.

## 검증 및 직접 조치

플레이 결과에서 다음 항목을 확인한다.

- SSH 서비스 실행 여부
- 변경 전·후 RPM 또는 DEB 전체 패키지 버전
- `ssh -V`와 `sshd -V` 출력
- 활성 저장소에 남은 OpenSSH 관련 업데이트가 없는지 여부
- 변경 후 `sshd -t` 성공과 SSH 서비스 실행 상태
- OS가 표시한 서비스 재시작 필요 정보

패키지가 변경됐다면 기존 SSH 연결은 유지한 상태에서 별도의 새 터미널로 신규
SSH 접속을 먼저 확인한다. 이후 승인된 유지보수 시간에 콘솔 또는 대체 접속 수단을
확보하고 SSH 서비스를 직접 재시작한다. 재부팅이 필요하면 조직의 서버 재부팅
절차에 따라 별도 수행한다.

## 예외 및 롤백

- 내부 저장소가 공식 보안 패키지를 아직 동기화하지 않았다면 조치를 완료로
  판정하지 않고 저장소 동기화 후 다시 실행한다.
- 버전 고정 또는 제외 설정 때문에 업데이트가 남으면 자동으로 우회하지 않고
  해당 정책을 검토한다.
- source build 또는 별도 경로에 설치한 OpenSSH는 이 플레이북의 대상이 아니다.
- 패키지 downgrade는 SSH 접속 장애 위험이 있으므로 자동 롤백하지 않는다.
  장애 시 콘솔에서 VM 스냅샷 또는 승인된 이전 패키지 세트로 복구한다.
