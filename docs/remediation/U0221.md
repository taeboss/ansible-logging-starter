# U0221 - world writable 파일 점검

## 진단 기준

- 양호: 시스템 중요 파일에 world writable 권한이 없거나, 해당 권한이 필요한
  파일은 설정 이유와 관리 주체를 확인하고 예외로 승인했다.
- 취약: 시스템 중요 파일에 world writable 권한이 있지만 설정 이유와 필요성을
  확인하지 않았다.

world writable은 파일의 기타 사용자 권한에 쓰기 비트가 설정되어 모든 로컬
사용자가 해당 파일을 변경할 수 있는 상태를 의미한다. 중요 설정이나 실행 파일이
이 상태이면 비인가 변경, 악성 내용 삽입 또는 서비스 오동작으로 이어질 수 있다.

## 진단 예시

진단 결과로 제공된 절대 경로마다 파일 형식, 소유자, 권한, 링크 여부와 사용
프로세스를 확인한다.

```bash
sudo stat -c '%F %U %G %a %n' -- /absolute/path/to/file
sudo readlink -f -- /absolute/path/to/file
sudo lsof -- /absolute/path/to/file
```

추가 현황 조사가 필요하면 파일시스템 경계를 넘지 않고 일반 파일을 조회한다.

```bash
sudo find / -xdev -type f -perm -0002 -print
```

`/proc`, `/sys`, `/dev`, 컨테이너·네트워크 마운트와 별도 파일시스템은 특성이
다르므로 대상 범위를 명시해서 별도로 점검한다. world writable 디렉터리는
일반 파일과 조치 기준이 다르며 sticky bit까지 함께 확인해야 한다.

## 권고 조치 방법

설정 이유가 없고 파일이 계속 필요하면 기타 사용자의 쓰기 권한만 제거한다.

```bash
sudo chmod o-w -- /absolute/path/to/file
```

불필요한 일반 파일로 확인된 경우에만 백업 또는 복구 가능성을 확보한 후 정확한
절대 경로를 지정해 삭제한다.

```bash
sudo rm -- /absolute/path/to/file
```

일반 파일 한 개를 삭제할 때 재귀 삭제 옵션인 `rm -rf`를 사용하지 않는다.
디렉터리, 심볼릭 링크, 마운트 지점 또는 와일드카드를 대상으로 삭제하지 않으며,
삭제 필요성이 확정되지 않으면 권한도 변경하지 않는다.

## 구현 상태

| 구분 | Red Hat 계열 | Ubuntu |
|---|---|---|
| 상태 | ⚪ 미구현(검토 보류) | ⚪ 미구현(검토 보류) |
| 실행 플레이북 | 미작성 | 미작성 |
| Role 태스크 | 미작성 | 미작성 |
| 현재 자동 조치 | 없음 | 없음 |

현재 저장소에는 U0221 점검 또는 설정 변경 플레이북이 없다. world writable 파일의
권한을 변경하거나 파일을 삭제하지 않는다.

## 미구현 사유와 우려사항

world writable 권한은 취약한 설정일 수 있지만 애플리케이션의 공유 파일,
임시 작업 경로 또는 운영 절차에 따라 의도적으로 사용될 수도 있다. 경로만으로
필요 여부를 일괄 판단하면 업무 서비스 장애나 데이터 손실이 발생할 수 있다.

다음 사항을 서버별로 확인해야 하므로 자동 조치를 보류한다.

1. 진단된 대상이 일반 파일, 디렉터리, 심볼릭 링크 또는 마운트 지점인지 여부
2. 파일의 소유자, 생성 주체, 패키지 소유 여부와 사용하는 서비스·프로세스
3. world writable 권한이 필요한 업무상 이유와 승인된 예외 여부
4. 권한 제거 후 서비스 계정과 일반 사용자의 정상 쓰기 가능 여부
5. 삭제 전 백업, 재생성 주체, 데이터 복구 방법과 서비스 영향
6. 패키지 업데이트, 애플리케이션 또는 임시파일 생성기가 권한을 다시 만드는지 여부

## 직접 조치 방침

서버별 진단 결과를 담당자가 검토한 후 다음 중 하나로 개별 처리한다.

- 필요 파일이고 world writable이 불필요하면 `chmod o-w`로 권한을 제거한다.
- 불필요한 일반 파일로 확인되면 백업 후 정확한 절대 경로를 지정해 삭제한다.
- 권한이 반드시 필요하면 설정 이유, 소유자, 사용 서비스와 승인자를 예외 목록에
  기록하고 정기적으로 재검토한다.
- 판단에 필요한 정보가 부족하면 변경하지 않고 담당 서비스 관리자에게 확인한다.

## 조치 후 확인

권한을 변경했다면 대상 파일의 최종 상태와 관련 서비스 동작을 확인한다.

```bash
sudo stat -c '%F %U %G %a %n' -- /absolute/path/to/file
```

삭제했다면 파일이 불필요했다는 승인 기록, 백업 위치와 관련 서비스의 정상 상태를
남긴다. 작업 결과는 서버명, 대상 절대 경로, 변경 전·후 권한, 처리 사유와
담당자를 포함하여 관리한다.
