# U0509 - glibc 버전 취약성

## 진단 기준

- 양호: 지원 중인 OS 공식 저장소에서 제공하는 glibc 보안 수정 패키지가
  적용되어 있고 추가로 설치할 glibc 관련 업데이트가 없다.
- 취약: glibc 관련 보안 업데이트가 남아 있거나, 지원이 종료된 패키지 또는
  출처를 확인할 수 없는 별도 설치본을 사용한다.

제공된 `gethostbyname_r()` 점검 코드는 GHOST 취약점(CVE-2015-0235)을 확인하는
코드이다. 이 결함은 upstream glibc 2.18에서 수정됐으므로 glibc 2.35를
2.39보다 낮다는 이유만으로 해당 취약점에 취약하다고 판정하지 않는다.

Red Hat과 Ubuntu는 안정성을 위해 보안 수정사항을 기존 upstream 버전에
백포트한다. 따라서 `getconf GNU_LIBC_VERSION`의 upstream 숫자만 비교하지 않고
RPM·DEB 전체 패키지 버전, 공식 보안 공지와 추가 업데이트 여부를 기준으로
판정한다. GCC가 없다는 사실은 점검 코드를 컴파일할 수 없다는 뜻일 뿐 glibc의
취약성 부재를 증명하지 않으므로 참고 정보로만 수집한다.

## 구현 상태

| 구분 | Red Hat 계열 | Ubuntu |
|---|---|---|
| 실행 플레이북 | `playbooks/controls/U0509.yml` | `playbooks/controls/U0509.yml` |
| Role 태스크 | `u0509_redhat.yml` | `u0509_ubuntu.yml` |
| 대상 패키지 | 설치된 `glibc*`, `nscd` | 설치된 `libc6*`, `libc-bin`, `libc-dev-bin`, `locales*`, `nscd` |
| 패키지 관리자 | DNF 또는 DNF5 자동 선택 | APT |
| 업데이트 범위 | 대상 패키지만 `latest` | 대상 패키지만 `latest` |
| 서비스 재시작·재부팅 | 결과만 확인 | 결과만 확인 |

전체 상태는 🟡 부분 적용이다. 패키지 업데이트는 자동 조치하며 업무 서비스
재시작 또는 서버 재부팅은 담당자가 영향도를 확인한 후 직접 수행한다.

## 자동 조치

플레이북은 다음 순서로 작업한다.

1. 대상 OS와 현재 설치된 패키지를 확인한다.
2. 설치된 glibc 실행 라이브러리와 관련 패키지만 조치 대상으로 선정한다.
3. GCC 실행 파일 존재 여부를 참고 정보로 확인한다.
4. 변경 전 RPM 또는 DEB 전체 패키지 버전과 glibc 실행 버전을 기록한다.
5. 활성화된 OS 공식 저장소에서 대상 패키지만 최신 버전으로 업데이트한다.
6. 같은 패키지에 추가 업데이트가 남았는지 점검 모드로 다시 확인한다.
7. 변경 후 패키지·실행 버전과 재부팅 또는 서비스 재시작 필요 상태를 출력한다.

전체 OS 업데이트, GCC 설치·업데이트, 취약점 점검 코드 컴파일, upstream glibc
직접 설치, 서비스 재시작과 서버 재부팅은 수행하지 않는다. Ubuntu는 패키지
작업 중 서비스가 자동 재시작되지 않도록 `policy_rc_d=101`을 임시 적용한다.

## 실행 방법

먼저 대상 한 대에서 공식 저장소 접근과 변경 예정 패키지를 확인한다.

```bash
ansible-playbook playbooks/controls/U0509.yml \
  --limit TARGET --check --diff
```

점검 결과를 검토한 후 `--check --diff`를 제거하여 실제 적용한다. 통합
플레이북이 facts로 대상 OS를 판별하며 한 번에 한 서버만 처리한다.

## 검증 및 직접 조치

플레이 결과에서 다음 항목을 확인한다.

- 변경 전·후 RPM 또는 DEB 전체 패키지 버전
- `getconf GNU_LIBC_VERSION` 출력
- 활성 저장소에 남은 glibc 관련 업데이트가 없는지 여부
- 재부팅 필요 여부
- Ubuntu에서 `needrestart`가 제공하는 재시작 대상

glibc는 다수의 실행 중인 프로세스가 사용하는 핵심 라이브러리다. 업데이트된
라이브러리를 기존 프로세스가 계속 사용하면 유지보수 시간에 업무 담당자와
협의하여 해당 서비스를 재시작한다. 재부팅 필요 결과가 표시되거나 개별 서비스
재시작으로 안전하게 전환하기 어려우면 조직의 서버 재부팅 절차에 따라 수행한다.

## 예외 및 롤백

- 내부 저장소가 공식 보안 패키지를 아직 동기화하지 않았다면 조치를 완료로
  판정하지 않고 저장소 동기화 후 다시 실행한다.
- 버전 고정 또는 제외 설정 때문에 업데이트가 남으면 자동으로 우회하지 않고
  해당 정책을 검토한다.
- 별도 설치한 upstream glibc는 이 플레이북의 대상이 아니며 별도 검토한다.
- glibc downgrade는 시스템 전체 의존성과 실행 프로세스에 영향을 주므로 자동
  롤백하지 않는다. 파일럿 서버에서 먼저 적용하고 장애 시 VM 스냅샷 또는
  승인된 이전 패키지 세트를 사용하여 관련 패키지를 일관되게 복구한다.
