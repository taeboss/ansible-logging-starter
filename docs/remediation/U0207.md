# U0207 - /etc/hosts 파일 권한 설정

## 진단 기준

- 양호: `/etc/hosts`의 소유자가 `root`이고 권한이 `0600` 이하로 설정되어 있다.
- 취약: 소유자가 `root`가 아니거나 그룹·기타 사용자에게 접근 권한이 있다.

이 플레이북은 정상적인 읽기 권한을 가진 `0400`과 읽기·쓰기 권한을 가진
`0600`을 양호한 권한으로 인정한다. 실행 비트가 있거나 그룹·기타 사용자 권한이
있는 경우에는 `0600`으로 설정한다.

## 서비스 영향 주의

`/etc/hosts`는 IP 주소와 호스트 이름의 정적 매핑에 사용되며 변경사항은 일반적으로
즉시 반영된다. 기본 권한인 `0644`를 `0600`으로 제한하면 일반 사용자 권한으로
실행되는 프로세스가 파일을 직접 읽지 못할 수 있다. 해당 프로세스가 DNS가 아닌
`/etc/hosts`의 전용 항목에 의존하면 이름 해석이 실패할 가능성이 있다.

따라서 서비스 영향이 항상 없다고 단정하지 않고 파일럿 서버에서 업무 계정과
서비스 계정의 이름 해석을 확인한 후 확대 적용한다.

## 조치 방법

일반 파일이면 다음과 같이 소유자와 권한을 설정한다.

```bash
ls -al /etc/hosts
sudo chown root /etc/hosts
sudo chmod 600 /etc/hosts
```

`/etc/hosts`가 심볼릭 링크라면 링크 자체가 아니라 `readlink -f`로 확인한 원본
파일에 동일한 소유자와 권한을 적용한다.

```bash
readlink -f /etc/hosts
sudo chown root LINK_TARGET
sudo chmod 600 LINK_TARGET
```

## 구현 상태

| 구분 | Red Hat 계열 | Ubuntu |
|---|---|---|
| 실행 플레이북 | `playbooks/controls/U0207.yml` | `playbooks/controls/U0207.yml` |
| Role 태스크 | `u0207_redhat.yml` | `u0207_ubuntu.yml` |
| 변경 대상 | `/etc/hosts` 또는 링크 원본의 소유자와 권한 | `/etc/hosts` 또는 링크 원본의 소유자와 권한 |
| 양호 권한 | `0400`, `0600` | `0400`, `0600` |
| 서비스 재시작·재부팅 | 불필요 | 불필요 |

전체 상태는 ✅ 적용 가능이다. 소유자와 권한은 자동 조치하며 서비스 재시작이나
서버 재부팅은 필요하지 않다. 다만 업무 서비스 계정의 이름 해석 확인은 운영자가
파일럿 단계에서 수행한다.

## 자동 조치

플레이북은 다음 순서로 작업한다.

1. `/etc/hosts`가 일반 파일인지 확인하고, 심볼릭 링크이면 원본 파일을 추적한다.
2. 링크 원본이 일반 파일인지 확인하고 변경 전 소유자, 권한과 SHA-256을 기록한다.
3. Ansible 접속 계정으로 현재 서버 호스트 이름을 조회한다.
4. 소유자가 `root`가 아니면 `root`로 변경한다.
5. 권한이 `0400` 또는 `0600`이 아니면 `0600`으로 변경한다.
6. 변경 후 파일 내용 SHA-256, 소유자와 권한을 검증한다.
7. 변경 전 가능했던 일반 계정 호스트 이름 조회가 계속 가능한지 확인한다.

파일 내용과 그룹은 변경하지 않는다. 검증에 실패하면 변경 전 소유자와 권한으로
자동 복구를 시도한 후 플레이를 실패로 종료한다.

## 실행 방법

먼저 대상 한 대에서 현재 권한과 예상 변경을 확인한다.

```bash
ansible-playbook playbooks/controls/U0207.yml \
  --limit TARGET --check --diff
```

점검 결과를 검토한 후 `--check --diff`를 제거하여 실제 적용한다. 통합
플레이북이 facts로 대상 OS를 판별하며 한 번에 한 서버만 처리한다.

## 검증 및 직접 확인

플레이 결과와 대상 서버에서 다음 항목을 확인한다.

```bash
sudo stat -c '%U %G %a %n' /etc/hosts
sudo sha256sum /etc/hosts
getent hosts "$(hostname)"
```

업무 서비스가 별도 계정으로 실행된다면 해당 계정에서도 서비스가 사용하는
호스트 이름을 직접 확인한다.

```bash
sudo -u SERVICE_USER getent hosts REQUIRED_HOSTNAME
```

## 예외 및 롤백

- 심볼릭 링크이면 링크가 가리키는 원본 일반 파일을 조치한다. 끊어진 링크이거나
  원본이 일반 파일이 아니면 자동 조치를 중단한다.
- 컨테이너 bind mount 또는 외부 관리 대상이면 해당 관리 주체의 정책을 확인한다.
- cloud-init, 구성관리 도구 또는 가상화 플랫폼이 권한을 다시 변경하는지 확인한다.
- 이름 해석 장애가 발생하면 콘솔에서 변경 전 권한으로 복구하고 서비스 계정의
  `/etc/hosts` 의존성과 DNS 등록 상태를 확인한다.
- 파일 내용 변경은 U0207의 자동 조치 범위가 아니다.
