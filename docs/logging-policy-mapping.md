# 로깅 정책 매핑

정책 문구를 Ansible 설정, 정기 점검, 외부 시스템 영역으로 나누어 관리한다.

| 정책 | Ansible 구현 | 현재 상태 | 외부 또는 사람의 역할 |
|---|---|---|---|
| 로그인 전 시스템 정보 비노출 | 고정 `/etc/issue`, `/etc/issue.net`, SSH Banner | 구현 | 승인 경고문 확정 |
| 인가 사용자 전용 경고 | `login_warning_text` 변수 | 구현 | 법무·보안 문구 승인 |
| 로그 관리자만 관리 | 그룹·파일 권한·sudo 정책 | 부분 구현 | 관리자 명단과 권한 승인 |
| 공인 NTP 동기화 | chrony 템플릿과 서비스 | 구현 | 외부 서버 사용 승인·가용성 확인 |
| 월 1회 시간 오차 점검 | `30-monthly-time-check.yml` | 부분 구현 | 플레이북 구현 완료, AWX/CI 스케줄 등록 필요 |
| 반기 네트워크 서비스 점검 | `ss` 결과 보고서 | 수집 구현 | 승인 포트 결정과 특이사항 판단 |
| 최근 로그인 사용자 | `lastlog`, wtmp/lastlog 감사 | 구현 | 중앙 보존 및 검토 |

| 접속 터미널과 위치 | SSH VERBOSE, 세션·원격 IP | 부분 구현 | 물리 위치는 VPN/NAC/CMDB 연계 |

| 데이터·자원 접근 성공·실패 | 중요 경로 watch, EACCES/EPERM 규칙 | 부분 구현 | DB·앱 감사로그 설정 |
| 시스템·커널·부팅 이벤트 | journald 영구 저장 | 구현 | 중앙 장기 보존 |
| 주요 설정파일 | audit watch 규칙 | 구현 | 중요 경로 목록 승인 |
| cron 실행 이력 | cron 설정 변경만 감사 | 미완성 | 실행 로그 범위 결정 |
| 패키지 업데이트 이력 | 패키지 관리자 audit 규칙 필요 | 미구현 | 허용 변경 절차 |
| 사용자 명령 실행 | `execve`, 로그인 auid 기록 | 구현 | 민감 명령 인자 보호 |
| 1년 이상 보관 | journald 365일 설정 | 부분 구현 | 중앙 저장 용량·보존정책 |
| 주간 무결성·용량 점검 | 용량·체크섬·audit 상태 | 부분 구현 | 기준 체크섬 승인과 결과 검토 |

## 접근 실패 감사의 책임 경계

Ansible은 auditd 규칙 파일을 배포하고 `augenrules --load`로 적용하며,
`auditctl -l`로 활성 상태를 검증할 수 있다. auditd는 실제 이벤트를 기록한다.
이벤트의 실시간 상관분석, 경보와 조사 판단은 SIEM 또는 담당자가 수행한다.

현재 규칙은 일반 사용자의 다음 실패를 기록한다.

- `open`, `openat`, `creat`, `truncate`, `ftruncate`
- `EACCES`, `EPERM`
- 로그인 사용자 식별이 가능한 `auid>=1000`

삭제, 이름변경, 디렉터리 생성, 권한·소유자 변경 실패는 추후 syscall 규칙을
추가해야 한다.
